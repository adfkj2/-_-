# 模块与需求对应

本文件说明 F01 至 F06 的实现落点，便于评审时按“需求 → 代码 → 接口 → 数据”逐层核对。

## 需求到代码

| 需求 | 验收条件 | 代码位置 |
| --- | --- | --- |
| F01 集中账号登录 | AC-01-1 至 AC-01-4 | `security/DbUserDetailsService`（状态与锁定）、`security/SsoAuthenticationSuccessHandler`（会话与审计）、`security/UnifiedLoginFailureHandler`（统一提示） |
| F02 跨系统单点登录 | AC-02-1 至 AC-02-4 | `config/AuthorizationServerConfig`（客户端、PKCE、授权码有效期）、`app-a`/`app-b` 的 `application.yml` |
| F03 受保护资源访问控制 | AC-03-1 至 AC-03-4 | `security/SessionValidityFilter`（会话失效即拒绝）、各客户端 `SecurityConfig`（默认拒绝） |
| F04 退出登录 | AC-04-1 至 AC-04-4 | `session/CenterSessionLogoutHandler`、`web/LogoutApiController` |
| F05 会话有效期处理 | AC-05-1 至 AC-05-4 | `session/SessionPolicy`、`session/SessionService`、`session/PolicyService` |
| F06 用户登录会话管理 | AC-06-1 至 AC-06-3 | `web/MeSessionController` |

## 需求到数据

| 数据对象 | 表名 | 本阶段用途 |
| --- | --- | --- |
| 用户 | sys_user | 登录主体、状态、锁定、认证版本 |
| 角色 | sys_role、user_role | 只读，用于装配权限 |
| 中心会话 | auth_session | 创建、刷新、过期、撤销 |

## 设计取舍

1. **会话标识即容器会话 ID**：`auth_session.sid` 与 `HttpSession#getId()` 一致，登录成功后写入，另存 SHA-256 摘要用于校验。这样无需额外的会话框架即可在过滤器中判定有效性。
2. **时限快照**：登录时把当前策略写入 `idle_timeout_seconds` 与 `absolute_expires_at`，之后修改策略只影响新会话（BR-13）。
3. **会话失效的处理位置**：放在安全过滤器链内、`UsernamePasswordAuthenticationFilter` 之后，页面请求跳转登录页，接口请求返回 401（BR-19）。
4. **登录失败不区分原因**：`DbUserDetailsService` 对不存在、停用、锁定分别抛出标准异常，界面统一显示“账号或密码错误”，真实原因只进审计（BR-07）。
5. **客户端按机密客户端实现**：与设计文档第 5 章“框架客户端表保存客户端认证方式与密钥”一致，采用 `client_secret_basic` + PKCE S256；密钥以散列保存，双方通过 `SSO_APP_A_SECRET` / `SSO_APP_B_SECRET` 对齐，避免明文入库。
6. **授权记录暂用内存**：`RegisteredClient` 与授权状态由授权服务器内存仓库保存，重启后需要重新登录。F13 应用管理与 F04 的跨端授权撤销在接入数据库仓储后补齐。

## 已知限制

- 认证中心重启后签名密钥变化，已签发令牌失效，属预期行为。
- 客户端登记仍为内存仓库，重启后密钥按配置重建；接入 F13 应用管理后改为数据库保存。
- 客户端登记仍为内存仓库，重启后密钥按配置重建；接入 F13 应用管理后改为数据库保存。
- 全局退出只撤销中心会话与浏览器会话，授权服务器内存中的授权记录随之失效，但未做逐个清理；接入数据库仓储时一并处理。
- 未实现登录失败次数累计与锁定（F11），当前 `failed_count` 与 `locked_until` 由账号模块写入。
