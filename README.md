# 统一认证登录 —— 软件工程课程设计

面向多业务系统的**统一身份认证与单点登录**系统：一套账号在教务信息服务 A 与图书信息服务 B 之间一次登录、免重复鉴权，管理员集中维护账号、角色、应用授权与审计记录。

本仓库同时包含**过程文档**（开发计划、需求规格说明书、概要与详细设计、测试计划与用例、UML 模型、汇报材料）与**已完成的功能实现**（认证中心 + 两个演示业务系统）。

项目依据课程设计要求，按项目启动、需求分析、系统设计、软件实现、软件测试、交付验收的顺序推进，共 10 周。

- 周期：2026-10-08 至 2026-12-16

## 已实现的功能（F01–F06）

`sso-platform/` 中已落地的是需求清单里由李鹏负责的六项功能，三个服务同机部署：

```
浏览器 ── 中心会话 SESSION_CENTER ──┐
   ├─ app-a :8081 (SESSION_A) ─────┤  OIDC 授权码 + PKCE S256
   └─ app-b :8082 (SESSION_B) ─────┘  / 令牌内省 / 统一退出
                    │
            认证中心 :9000 ── MySQL 8.4
```

| 需求 | 能力 | 代码位置 |
| --- | --- | --- |
| F01 集中账号登录 | 表单登录、账号状态与锁定校验、统一失败提示、登录后建立中心会话 | `security/DbUserDetailsService`、`SsoAuthenticationSuccessHandler`、`UnifiedLoginFailureHandler` |
| F02 跨系统单点登录 | 授权码 + PKCE S256、复用中心会话、回调地址精确匹配、令牌 10 分钟 | `config/RegisteredClientFactory`、`AuthorizationServerConfig` |
| F03 受保护资源访问控制 | 默认拒绝；接口未认证 401、页面 302 转登录；会话无效即拒绝 | `security/SessionValidityFilter`、各服务 `SecurityConfig` |
| F04 退出登录 | 统一退出撤销当前浏览器会话；接口支持 `scope=local` 与 `scope=global` | `session/CenterSessionLogoutHandler`、`web/LogoutApiController` |
| F05 会话有效期处理 | 空闲 30 分钟、绝对 8 小时，创建时快照，边界按大于等于判定 | `session/SessionPolicy`、`SessionService` |
| F06 用户登录会话管理 | 本人会话列表、结束指定会话、越权 403 | `web/MeSessionController` |

尚未实现：F07 至 F12（账号、注册审核、资料、密码、失败锁定、角色）、F13 至 F18（应用管理、应用授权、审计查询、统计、策略配置、异常事件）。相关读取接口已在代码中以只读方式预留（`UserRoleReader`、`PolicyService`、`AuditWriter`）。

## 快速开始

```bash
# 1. 建库建表
mysql -u root -p < sso-platform/db/init.sql

# 2. 建应用账号（示例，按本机情况修改）
#    CREATE USER 'sso'@'localhost' IDENTIFIED BY '***';
#    GRANT ALL PRIVILEGES ON sso.* TO 'sso'@'localhost';

# 3. 构建
cd sso-platform && mvn -B package

# 4. 按顺序启动（应用启动时需要访问认证中心的 JWKS）
java -jar sso-auth-server/target/sso-auth-server-0.1.0.jar
java -jar app-a/target/app-a-0.1.0.jar
java -jar app-b/target/app-b-0.1.0.jar
```

打开 <http://127.0.0.1:8081/> 应跳转认证中心登录页；登录后回到 A；再打开 <http://127.0.0.1:8082/> 应免密进入。

演示账号由 `DataSeeder` 幂等写入：`alice01`（可访问 A 与 B）、`aonly01`（仅 A）、`pending01`（待审核）、`disabled01`（停用）、`admin01`（管理员）。口令通过 `sso.demo.password` 与 `sso.demo.admin-password` 配置，**仅用于隔离环境**。

## 关键约定

- **端口**：认证中心 9000，应用 A 8081，应用 B 8082。
- **Cookie 名**：`SESSION_CENTER`、`SESSION_A`、`SESSION_B`。浏览器 Cookie 不按端口隔离，三个服务必须使用不同名称，否则无法演示单点登录。
- **客户端**：两个业务系统按机密客户端登记（`client_secret_basic` + 强制 PKCE S256），密钥以散列保存，用 `SSO_APP_A_SECRET` 与 `SSO_APP_B_SECRET` 覆盖。
- **令牌**：授权码 60 秒一次性、访问令牌 10 分钟、不签发刷新令牌。
- **协议**：演示环境为隔离网络内的本地 HTTP；HTTPS 由部署配置切换，代码不做区分。

## 已知限制

- 认证中心重启后签名密钥重新生成，已签发令牌失效，属演示环境的预期行为。
- 客户端登记与授权状态保存在内存，重启后需重新登录；接入 F13 应用管理后改为数据库保存。
- 业务系统侧的“撤权后即时 403”需要内省结果与会话状态联动，属 F03 的剩余工作。
- 审计只写不查（F15、F16 未实现），事件类型与字段已按数据字典落库。
