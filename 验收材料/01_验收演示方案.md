## 2 演示动线

八条动线按“从零开始”的顺序排列，前一条的后置状态是后一条的前置条件。现场按顺序走，不跳步。

<!--cols:6,12,18,20,30,14-->

| 序号 | 动线 | 前置数据 | 操作 | 预期可观测结果 | 对应用例 |
| --- | --- | --- | --- | --- | --- |
| 1 | 首次登录 A | alice01 为 ACTIVE；APP_A 启用；浏览器 1 无会话 | 浏览器 1 打开 A 的受保护首页，跳转中心登录页，输入 alice01 与密码 | 回到 A 原目标页，页面显示 alice01；数据库 auth_session 新增 ACTIVE 记录；审计出现 LOGIN_SUCCESS | TC-F01-A |
| 2 | 免密进入 B | 承接第 1 条，浏览器 1 中心会话有效 | 同一浏览器打开 B 的受保护首页 | 不出现登录页直接进入；B 显示同一用户名；审计出现 SSO_AUTHORIZE | TC-F02-A |
| 3 | 换浏览器仍须登录 | 浏览器 2 全新，无任何 Cookie | 浏览器 2 打开 B | 出现登录页，未继承浏览器 1 的登录态 | TC-F02-B |
| 4 | 直连受保护接口被拒 | 浏览器 2 未登录 | 在地址栏直接请求 A 的受保护接口路径 | 返回 401，响应体为错误码结构，不含任何业务数据 | TC-F03-B |
| 5 | 撤权后即时失效 | 浏览器 1 已登录 A、B；admin01 已登录管理台 | 管理台移除 alice01 角色对 A 的授权，回到浏览器 1 点击 A 的受保护操作 | 下一次请求返回 403；B 不受影响 | TC-F14-B |
| 6 | 停用账号双端失效 | 浏览器 1、浏览器 2 分别以同一账号登录 | 管理台停用该账号，两端各点一次受保护操作 | 两端均返回 401，且该账号不能再次登录（提示与密码错误一致） | TC-F07-B |
| 7 | 改密挤出旧会话 | 两个浏览器以 alice01 登录 | 浏览器 1 改密，浏览器 2 刷新受保护页 | 浏览器 2 被要求重新登录；旧密码登录失败，新密码成功 | TC-F10-A |
| 8 | 统一退出与审计收尾 | 浏览器 1 中 A、B 均在线 | 执行统一退出，再回 A、B 各点一次；管理台查审计与统计 | A、B 均要求重新登录；审计可按用户与应用过滤到上述全部事件 | TC-F04-B、TC-F15-A |

执行要点：

- 第 3 条必须用**另一个浏览器**（或另一个浏览器配置文件），不能开无痕窗口了事，无痕与普通窗口共享部分状态时容易误判。
- 第 5、6 条的“下一次请求”必须点受保护操作或接口，刷新首页不足以证明，因为首页可能被缓存。
- 第 8 条结束前不要清理数据库，审计页要现场展示，这是“系统真跑过”的证据。

## 3 现场环境与启动

### 3.1 主口径：本机三端口、HTTP、独立 Cookie 名

| 项目 | 取值 |
| --- | --- |
| 认证中心 | http://127.0.0.1:9000 |
| 应用 A、B | http://127.0.0.1:8081、http://127.0.0.1:8082 |
| 会话隔离 | 三个服务各用独立 Cookie 名：SESSION_CENTER、SESSION_A、SESSION_B |
| 域名与证书 | 不改 hosts，不使用证书 |
| 数据库 | 本机 MySQL 8.4，库名 sso，字符集 utf8mb4 |
| 运行时 | JDK 21，三个可执行 jar，本地依赖已预热 |
| 启动方式 | 双击 start-all.cmd，按“数据库→中心→A→B”顺序启动并逐个探活 |

这样选的理由：现场最容易翻车的三件事是改 hosts 需要管理员权限、自签证书要装信任库、浏览器反复拦截非受信证书。三端口加 HTTP 把这三件事全部去掉，现场只剩“双击、等探活、打开页面”。而单点登录的验收点（会话是否共享、撤权是否立刻生效）与是否 HTTPS 无关，用三个不同 Cookie 名同样能把三个会话域彻底隔开。

汇报口径一句话：三个服务跑在同一台机器的三个端口上，浏览器 Cookie 不按端口隔离，所以给每个服务设了独立 Cookie 名，A 和 B 才是两个真正独立的应用，单点登录才有意义。

与需求 NFR01（全链路 HTTPS）的关系：演示环境使用 HTTP，属隔离网络内的本地演示，仅此一项偏离，不作为 NFR01 的验收证据；HTTPS 的配置能力保留在 https profile 中，需要时按 3.3 启用。

### 3.2 启动与探活顺序

1. 启动 MySQL 服务，执行 init.sql（幂等，可重复执行）。
2. 启动认证中心，等待健康检查返回 UP；未 UP 不启动后续服务，否则应用拿不到发现文档会反复重试。
3. 启动应用 A、B，各自等待健康检查 UP。
4. 用脚本自动打开三个地址，人工确认三个登录页均正常渲染。

预计冷启动 60 至 90 秒。现场留出 3 分钟余量，不压到最后一刻开机。

### 3.3 备选：需要 HTTPS 时

用 https profile 启动：同一组端口改走 https，配置自签证书与服务间共用信任库，浏览器需一次性信任例外。这条路径步骤更多、失败点更多，只在教师明确要求 HTTPS 时启用，且必须在第 9 周彩排中验证通过才允许上台。

### 3.4 现场检查清单

| 检查项 | 判据 |
| --- | --- |
| 笔记本电量 | 已接电源 |
| 端口空闲 | 9000、8081、8082 未被其他进程占用 |
| Cookie 名 | 三个服务配置互不相同，且不使用默认 JSESSIONID |
| 数据库 | 服务运行中，sso 库存在，四类演示账号齐全 |
| 三个服务 | 健康检查均 UP |
| 浏览器 | 至少两个可用浏览器，版本已记录 |
| 测试文档 | 纸质版页码完整，含勾选栏 |
| 演示账号 | admin01 与四类演示账号密码已核对 |
| 备份 | 整个运行目录已复制到 U 盘，含 init.sql |

## 4 演示数据

| 账号 | 密码 | 状态 | 角色与授权 | 用途 |
| --- | --- | --- | --- | --- |
| admin01 | 首次登录强制修改 | ACTIVE | ADMIN | 管理台操作与审计查询 |
| alice01 | StudyPass2026! | ACTIVE | USER，授权 A、B | 动线 1、2、5、7、8 的主账号 |
| aonly01 | StudyPass2026! | ACTIVE | USER，仅授权 A | 验证“有 A 无 B”，第 5 条可替换使用 |
| pending01 | StudyPass2026! | PENDING | 无 | 验证待审核不能登录 |
| disabled01 | StudyPass2026! | DISABLED | 无 | 验证停用不能登录 |

| 对象 | 取值 |
| --- | --- |
| APP_A | 客户端标识 app-a，回调 http://127.0.0.1:8081/login/oauth2/code/sso |
| APP_B | 客户端标识 app-b，回调 http://127.0.0.1:8082/login/oauth2/code/sso |
| 角色 | ADMIN（系统角色，不可删）、USER |
| 授权 | USER 角色 → APP_A、APP_B；aonly01 另建只含 A 的角色或单独移除其 B 授权 |
| 策略 | 空闲 30 分钟、绝对 8 小时、失败窗口 15 分钟、阈值 5 次、锁定 15 分钟 |

演示账号的密码只用于隔离环境，不写入提交仓库。init.sql 必须幂等，现场可反复重置而不产生重复应用或重复角色。

## 5 现场流程与分工

| 版本 | 时长 | 内容 |
| --- | --- | --- |
| 短版 | 约 5 分钟 | 动线 1、2、4、5、8；跳过管理与审计细节，只点结论 |
| 标准版 | 约 12 分钟 | 八条全走，含管理台撤权、停用与审计查询 |
| 长版 | 约 18 分钟 | 标准版加待审核账号、停用账号登录、策略参数校验各一次 |

三人分工固定：一人操作键盘（熟悉全部动线，避免临场找菜单）、一人讲解对应需求与用例编号、一人翻纸质测试文档并记录勾选结果。讲解者不要同时操作，出错时容易互相打断。

## 6 打印与随身材料

1. 测试文档打印版：36 条功能用例与跨系统、性能用例全量，附现场勾选栏（实际结果、通过与否、执行人、时间）。
2. 动线卡片：A5 一页一条，正面写操作步骤，背面写预期结果与对应用例编号，供教师抽测时对照。
3. 环境检查单：第 3.4 节表格打印一页，进场后逐项打勾。
4. 应急卡：第 7 章的处置表打印一页，压在键盘旁。
5. 交付包 U 盘：含三个 jar、init.sql、证书、start-all.cmd、源码与全部文档。

## 7 应急与降级

| 症状 | 判断 | 处理 | 不要做 |
| --- | --- | --- | --- |
| 中心未启动完成 | 应用报连接拒绝或拿不到发现文档 | 等健康检查 UP 再启应用，或重启应用进程 | 不要反复刷新浏览器 |
| 端口被占用 | 启动日志报 Address already in use | 用备份目录改端口启动，并同步改回调白名单 | 不要现场结束不明进程 |
| 浏览器提示不安全 | 若启用 https 备选路径才会出现 | 改用主口径 HTTP，口头说明这是隔离网络内的演示环境 | 不要临时申请公网证书 |
| 数据库连接失败 | 三个服务均 UP 但登录 500 | 检查 MySQL 服务与账号权限，必要时用备份库文件恢复 | 不要手工改表结构 |
| 审计页无数据 | 查询条件过窄或时区不符 | 放宽到当天、清空用户与应用条件 | 不要现场补数据 |
| 时间不够 | 教师提示超时 | 立即切短版（5 分钟四条） | 不要临场加演未验证功能 |

## 8 与测试文档的映射与缺口

八条动线覆盖 P0 功能中的 F01、F02、F03、F04、F07、F10、F14、F15。未被主流程覆盖的 P0 功能为 F08（注册审核）、F11（失败锁定）、F13（应用管理）、F17（策略配置）、F18（异常事件）。

教师抽测若落到这些点，启用三条备选动线：

| 备选 | 动线 | 对应用例 |
| --- | --- | --- |
| 备 1 | 提交注册产生 PENDING，管理员批准后登录成功 | TC-F08-A、TC-F08-B |
| 备 2 | 连续 5 次错误密码后锁定，正确密码仍被拒；管理员解锁 | TC-F11-A、TC-F11-B |
| 备 3 | 登记应用时填非法回调被拒；把空闲时限改到越界值被拒 | TC-F13-B、TC-F17-B |

备选动线同样要在第 8 周的彩排中跑通，不能只写在纸上。
